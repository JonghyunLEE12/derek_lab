"ThreeRT"라는 이름을 어디서 보고 찾아봤는데 그런 이름의 기술은 따로 없었다. 대신 이름이 비슷한 **three-realtime-rt**가 걸렸다. three.js에 실시간 레이트레이싱 조명을 켜 주는 라이브러리다. 웹에서 레이트레이싱이 어디까지 되는지 궁금해서 문서를 읽어 보고, 공부한 걸 써먹을 겸 신주쿠 가부키초 一番街 밤거리를 만들어 봤다.

## three-realtime-rt는 뭘 해 주나

MIT 라이선스고 이번에 본 건 0.16.7 버전이다. 쓰는 법은 간단하다. 평소처럼 메시와 `MeshStandardMaterial`, 조명으로 장면을 만들고 `renderer.render(scene, camera)`를 부르던 자리만 바꾸면 된다.

```js
const rt = new RealtimeRaytracer(renderer);
rt.compileScene(scene);
// 매 프레임
rt.render(scene, camera);
```

`compileScene`이 장면의 지오메트리를 BVH(광선이 부딪히는 물체를 빨리 찾는 트리 구조)로 굽고 재질과 조명 표를 만든다. 그 뒤로는 매 프레임 `rt.render`가 알아서 다 한다. RT 코어는 안 쓰고 셰이더 계산만으로 광선을 쏴서 WebGL2만 되면 돌아간다.

## 한 프레임을 그리는 순서

README에서 제일 재밌게 읽은 부분이다. 이 라이브러리는 "하이브리드 디퍼드" 방식이라 화면 전체를 광선으로 그리지 않는다. 무엇이 보이는지는 평소처럼 래스터화로 그리고, 조명만 광선으로 계산한다.

1. **G-버퍼:** three.js가 래스터화로 색, 거칠기, 법선, 금속성, 월드 위치, 발광을 텍스처 여러 장에 나눠 그린다. 여기까지는 일반 렌더링과 비용이 비슷하다.
2. **레이트레이싱 조명:** 픽셀마다 조명 쪽으로 그림자 광선을 쏘고, 간접 조명(GI)용 광선을 한 번 튕긴다. 금속 표면은 반사 광선을, 유리는 굴절 광선을 쏜다. 결과는 색을 뺀 "빛의 양"만 저장한다. 그래야 노이즈를 걸러도 텍스처가 안 뭉개진다.
3. **시간 누적:** 이전 프레임 결과를 지금 화면 위치로 옮겨 와서 섞는다. 픽셀당 광선이 1개뿐이라 한 프레임만 보면 지글지글한데, 여러 프레임을 쌓으면 매끈해진다.
4. **노이즈 제거:** G-버퍼의 법선과 깊이를 보고 경계는 살리면서 흐리는 à-trous 필터를 돌린다.
5. **합성:** `색 × 빛 + 발광`을 합치고 안개, 톤매핑을 건다.
6. **TAA:** 매 프레임 카메라를 픽셀 단위 이하로 살짝 흔들고 누적해서 계단 현상을 없앤다.

조명은 기본적으로 절반 해상도로 계산하고 위 단계들로 다시 채운다. 적은 픽셀만 계산하고 시간으로 복원한다는 점에서 DLSS랑 생각이 같다고 README에 적혀 있다.

조명이 많아도 버티는 건 **ReSTIR** 덕분이다. 픽셀마다 후보 조명 몇 개를 뽑아 그중 영향이 큰 하나만 남기고, 그 선택을 이웃 픽셀과 이전 프레임에서 재사용한다. 그래서 조명이 6개든 96개든 픽셀당 그림자 광선 수가 같다. 이번 장면처럼 간판마다 조명을 다는 경우에 딱 맞았다.

움직이는 물체는 BVH를 두 단계로 나눠 처리한다. 정적인 건 한 번 구워서 GPU에 올려 두고, 움직이는 메시만 작은 BVH에 넣어 매 프레임 다시 맞춘다. 그래서 정적인 세계가 아무리 커도 움직이는 물체 갱신 비용은 그대로다.

## 쓰기 전에 알아야 할 제약

문서와 타입 정의를 읽어 보니 네온 거리를 만들려면 걸리는 게 몇 개 있었다. 표로 정리하고 하나씩 피해 갔다.

| 제약 | 어떻게 피했나 |
| --- | --- |
| 스스로 빛나는 메시는 진짜 면광원이 되지만 전체 삼각형 256개까지만 | 게이트와 큰 간판 몇 개만 면광원으로 쓰고 나머지 간판은 `rtNoAreaLight`로 화면에서만 빛나게 했다. 벽과 바닥에 번지는 색은 간판 앞에 둔 점광원 132개로 만들었다 |
| `InstancedMesh`는 한 개로 뭉개진다 | 쓰지 않고 같은 재질끼리 지오메트리를 합쳤다 |
| `Line`, `Sprite`, `Points`는 레이트레이싱에서 숨겨진다 | 전선을 얇은 원기둥으로 만들었다 |
| 반사는 금속성(metalness)이 있는 표면에만 생긴다 | 젖은 아스팔트에 금속성을 주고 웅덩이 부분은 거칠기를 낮췄다 |
| 발광 세기를 바꾸면 조명 계산에는 다시 컴파일하기 전까지 반영되지 않는다 | 네온 깜빡임은 재질 밝기와 옆 점광원 세기를 같이 바꾸는 방식으로 했다 |

마지막 제약이 처음엔 헷갈렸다. 화면에 보이는 발광은 G-버퍼가 재질을 매 프레임 직접 읽어서 바로 바뀌지만, 그 발광이 주변을 비추는 조명 표는 `compileScene` 시점에 굳는다. 그래서 깜빡임은 눈에 보이는 밝기와 실제로 비추는 점광원을 따로 같이 움직여야 한다.

완성된 장면은 정적 삼각형 140,968개, 움직이는 삼각형 11,538개, 점광원 132개, 면광원 삼각형 38개다.

## 사진 없이 전부 코드로

사진이나 3D 모델 파일은 하나도 안 썼다. 건물, 간판, 간판 글씨 텍스처, 바닥 질감까지 전부 브라우저에서 그때그때 만든다.

- 게이트를 지나면 거리 양쪽으로 건물 30채가 늘어서 있고, 옆 골목 2개에도 들어가 볼 수 있다.
- 세로 간판, 가로 빌보드, 1층 가게 불빛, 빨간 초롱, 자판기, 진입금지 표지까지 있다.
- 간판 글씨는 カラオケ, 焼肉, 居酒屋, 案内所 같은 일반 단어만 넣었다. 실제 상호나 로고는 없다.
- 사람도 24명 걸어 다닌다. 단순한 로우폴리 모양이고, 움직이는 BVH 갱신이 평균 3ms를 넘으면 멈추게 해 뒀다.

## 1인칭으로 걸어 다니기

장면 안을 직접 걸어 다닐 수 있다.

- **PC:** 화면을 클릭하면 마우스로 시점이 돌아간다. WASD나 방향키로 걷고 Shift로 뛴다. Esc를 누르면 마우스가 풀린다.
- **모바일:** 왼쪽 아래 조이스틱으로 걷고 오른쪽을 드래그해서 둘러본다.
- 건물이나 기둥은 못 뚫고 지나가고 벽을 따라 미끄러진다.
- 오른쪽 아래 미니맵에 위치와 방향이 나오고 Gate, Mid, End 버튼으로 순간이동할 수 있다.

<img src={`${base}/images/blog/kabukicho-rt/walk.jpg`} alt="게이트 아래를 지나 거리로 걸어 들어가는 1인칭 시점" />

걸으면 카메라가 계속 움직이니까 시간 누적이 깨지기 쉽다. 그래서 화면 가장자리 밖까지 조금 더 그려 두는 overscan을 켜고, 순간이동한 직후에는 `rt.resetAccumulation()`으로 이전 프레임 기록을 버리게 했다. 안 그러면 순간이동 직후 이전 장소가 잔상처럼 남는다.

## 젖은 바닥 반사를 한 번 고쳤다

라이브러리 반사는 조명 해상도가 낮아서 가까운 간판 글씨까지는 선명하게 못 비춘다. 그래서 화면에 보이는 간판은 화면 공간 반사(SSR)로 따로 비추고, 화면 밖 색은 라이브러리 반사가 채우게 나눴다.

그런데 처음 만든 SSR이 문제였다. 웅덩이에 비친 간판이 부드럽게 늘어지지 않고 네모난 계단 모양 줄무늬로 깨졌고, 게이트 앞 바닥에는 검은 얼룩까지 생겼다. 광선을 진행하는 간격이 거리에 비례해 커지는 데 비해 보정은 4번밖에 안 해서 반사된 글씨가 띄엄띄엄 끊긴 거였다.

진행 시작점을 픽셀마다 무작위로 흔들고, 보정을 7번으로 늘리고, 프레임끼리 누적하고, 세로로 빛을 번지게 해서 고쳤다. 무작위로 흔든 결과가 TAA로 누적되면서 매끈해지는 구조라, 앞에서 공부한 라이브러리 파이프라인이랑 같은 생각이다. 이 패스에 드는 시간은 0.47~1.11ms였다.

## 성능

Apple M4 Pro의 Chromium, 1920×1080에서 잰 값이다.

| 위치 | FPS |
| --- | ---: |
| 게이트 앞 | 60 |
| 거리 중간 | 53.1~55.4 |

라이브러리에 적응형 화질 조절이 켜져 있어서 프레임이 떨어질 것 같으면 내부 해상도를 알아서 낮춘다. 측정할 때 실제로 그린 해상도는 게이트 앞 1240×697, 거리 중간 942×530이었고 조명은 거기서 다시 20% 해상도로 계산했다. 화면이 전체적으로 살짝 뿌옇게 보이는 건 이것 때문이다. 화질 메뉴에서 Quality를 고르면 더 선명해진다.

## 배포

정적 파일뿐이라 fly.io에 nginx 컨테이너 하나로 올렸다. 도쿄 리전 shared-cpu-1x 256MB 머신 1대고, 아무도 안 들어오면 꺼진다. 라이브러리는 번들러 없이 쓰는 ES 모듈이라 import map으로 three.js, three-mesh-bvh, three-realtime-rt를 jsDelivr에서 버전을 고정해 불러온다. 첫 배포 때 IP 자동 할당이 실패해서 IPv4, IPv6를 따로 붙여 줬다. 배포 후 브라우저로 열어 보니 콘솔 오류 없이 52fps로 잘 돌았다.

## 아직 남은 것

1. 실제 휴대폰에서는 성능을 재 보지 않았다. 모바일은 M4 Pro에서 터치를 흉내 내서 확인한 게 전부다.
2. Safari, Firefox에서는 안 열어 봤다.
3. WebGL2가 안 되는 환경에서는 레이트레이싱 없이 일반 렌더링으로 바뀐다.
