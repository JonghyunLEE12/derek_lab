처음엔 그냥 "ThreeRT 기술" 좀 웹검색해 달라고 한 거였다. 막상 찾아보니 그런 이름의 기술은 없었다. 대신 이름이 비슷한 **three-realtime-rt**가 걸렸는데, three.js에 실시간 레이트레이싱 조명을 켜 주는 라이브러리다.

그래서 이걸로 신주쿠 가부키초 거리를 만들어 보기로 했다. 歌舞伎町一番街 빨간 게이트 사진을 한 장 던져 주고 이 거리를 웹사이트로 만들 수 있냐고 물었다. 주문은 딱 두 개였다. 최대한 그럴싸하게, 네온사인은 풍부하게.

결과물은 여기서 바로 볼 수 있다. 접속이 없으면 서버가 꺼져 있어서 처음 열 때는 몇 초 걸린다. WebGL2가 되는 데스크톱 브라우저로 보는 걸 추천한다.

- https://jonghyuns-kabukicho-rt.fly.dev

미리 말해 두면 코드는 한 줄도 내가 안 썼다. 요청 몇 줄 쓰고, 중간에 "진짜로 걸어 다닐 수 있게 해 줘"를 하나 더 얹은 게 전부다. 글에 나오는 숫자는 작업 기록이랑 결과물 README에서 가져왔다. 오전 10시쯤 검색으로 시작했는데 11시가 되기 전에 배포 주소를 받았다.

## three-realtime-rt는 뭘 해 주나

이름 그대로 three.js 장면에 레이트레이싱 조명을 켜 준다. MIT 라이선스고 이번에 쓴 건 0.16.7 버전이다.

화면에 뭐가 보이는지는 평소처럼 래스터화로 그리고, 조명만 광선을 쏴서 계산하는 하이브리드 방식이다. 광선은 BVH(광선이 부딪히는 물체를 빨리 찾는 트리 구조)를 상대로 쏜다. 덕분에 부드러운 그림자, 1회 반사 간접 조명(GI), 금속 반사, 유리 굴절, 빛줄기까지 나온다. RT 코어 없이 셰이더 계산만으로 돌아가서 WebGL2만 되면 된다.

붙이는 것도 간단하다. `renderer.render(scene, camera)`를 부르던 자리를 아래처럼 바꾸면 끝이다.

```js
const rt = new RealtimeRaytracer(renderer);
rt.compileScene(scene);
// 매 프레임
rt.render(scene, camera);
```

차이는 끄고 보면 바로 안다. 아래가 같은 장면에서 레이트레이싱만 끈 화면이다. 페이지 왼쪽 아래 버튼으로 직접 켰다 껐다 해 볼 수 있다.

<img src={`${base}/images/blog/kabukicho-rt/rt_off.jpg`} alt="레이트레이싱을 끈 같은 장면. 바닥과 건물이 어둡고 반사가 거의 없다" />

간판은 똑같이 빛나는데 그 빛이 바닥이랑 벽에 번지고 비치는 건 레이트레이싱을 켰을 때만 나온다.

## 제약부터 확인했다

바로 만들기 전에 Claude가 패키지를 받아서 README랑 타입 정의부터 읽었다. 네온 거리를 만들려고 보니 걸리는 게 몇 개 있었다.

| 제약 | 어떻게 피했나 |
| --- | --- |
| 스스로 빛나는 메시는 진짜 면광원이 되지만 전체 삼각형 256개까지만 | 게이트와 큰 간판 몇 개만 면광원으로 쓰고 나머지 간판은 `rtNoAreaLight`로 화면에서만 빛나게 했다. 벽과 바닥에 번지는 색은 간판 앞에 둔 점광원 132개로 만들었다 |
| `InstancedMesh`는 한 개로 뭉개진다 | 쓰지 않고 같은 재질끼리 지오메트리를 합쳤다 |
| `Line`, `Sprite`, `Points`는 레이트레이싱에서 숨겨진다 | 전선을 얇은 원기둥으로 만들었다 |
| 반사는 금속성(metalness)이 있는 표면에만 생긴다 | 젖은 아스팔트에 금속성을 주고 웅덩이 부분은 거칠기를 낮췄다 |
| 발광 세기를 바꾸면 조명 계산에는 다시 컴파일하기 전까지 반영되지 않는다 | 네온 깜빡임은 재질 밝기와 옆 점광원 세기를 같이 바꾸는 방식으로 했다 |

이 표는 그대로 작업 명세에 들어갔다. 완성된 장면은 정적 삼각형 140,968개, 움직이는 삼각형 11,538개, 점광원 132개, 면광원 삼각형 38개다.

## 사진 없이 전부 코드로

사진이나 3D 모델 파일은 하나도 안 썼다. 건물, 간판, 간판 글씨 텍스처, 바닥 질감까지 전부 브라우저에서 그때그때 만든다.

- 게이트를 지나면 거리 양쪽으로 건물 30채가 늘어서 있고, 옆 골목 2개에도 들어가 볼 수 있다.
- 세로 간판, 가로 빌보드, 1층 가게 불빛, 빨간 초롱, 자판기, 진입금지 표지까지 있다.
- 간판 글씨는 カラオケ, 焼肉, 居酒屋, 案内所 같은 일반 단어만 넣었다. 실제 상호나 로고는 없다.
- 사람도 24명 걸어 다닌다. 단순한 로우폴리 모양이고, 움직이는 BVH 갱신이 평균 3ms를 넘으면 멈추게 해 뒀다.

## 중간에 "걸어 다니게 해 줘"를 추가했다

처음 명세에도 앞뒤로 움직이는 기능은 있었다. 그런데 하는 김에 1인칭으로 진짜 걸어 다니게 해 달라고 작업 도중에 다시 부탁했다. 지금 조작은 이렇다.

- **PC:** 화면을 클릭하면 마우스로 시점이 돌아간다. WASD나 방향키로 걷고 Shift로 뛴다. Esc를 누르면 마우스가 풀린다.
- **모바일:** 왼쪽 아래 조이스틱으로 걷고 오른쪽을 드래그해서 둘러본다.
- 건물이나 기둥은 못 뚫고 지나가고 벽을 따라 미끄러진다.
- 오른쪽 아래 미니맵에 위치와 방향이 나오고 Gate, Mid, End 버튼으로 순간이동할 수 있다.

## 젖은 바닥 반사를 한 번 고쳤다

첫 결과물 스크린샷을 보니 웅덩이에 비친 간판이 이상했다. 부드럽게 늘어져야 할 반사가 네모난 계단 모양 줄무늬로 깨져 있었고, 게이트 앞 바닥에는 검은 얼룩까지 하나 있었다.

범인은 화면 공간 반사(SSR) 패스였다. 구현 워커가 라이브러리 반사 위에 따로 얹은 건데, 광선을 진행하는 간격이 거리에 비례해 커지는 데 비해 보정은 4번밖에 안 해서 반사된 글씨가 띄엄띄엄 끊겼다. 진행 시작점을 픽셀마다 무작위로 흔들고, 보정을 7번으로 늘리고, 프레임끼리 누적하고, 세로로 빛을 번지게 해서 고쳤다. 이 패스에 드는 시간은 0.47~1.11ms로 나왔다.

라이브러리 자체 반사만으로는 안 되는 이유도 있다. 조명 해상도가 낮아서 가까운 간판 글씨까지는 선명하게 못 비춘다. 그래서 화면에 보이는 간판은 SSR이 선명하게 비추고, 화면 밖 색은 라이브러리 반사가 채우는 식으로 나눠 맡기게 됐다.

## 역할 분담

내 환경에는 Orca라는 워커 오케스트레이션이 붙어 있어서 이번에도 그걸로 나눠 돌렸다.

| 역할 | 담당 | 하는 일 |
| --- | --- | --- |
| 코디네이터 | Claude Opus 5.5 | 검색, 라이브러리 문서 확인, 작업 명세 작성, 스크린샷 확인, 배포 |
| 구현 | Codex 워커 | 장면과 조작 구현, Playwright로 브라우저 검증과 스크린샷 |

Claude는 워커가 다 됐다고 보고해도 그대로 넘어가지 않고 스크린샷을 직접 열어 봤다. 반사 문제도 거기서 걸렸다. 다른 모델로 코드 리뷰를 돌리는 건 이번엔 생략했다.

## 성능

워커가 Apple M4 Pro의 Chromium, 1920×1080에서 잰 값이다.

| 위치 | FPS |
| --- | ---: |
| 게이트 앞 | 60 |
| 거리 중간 | 53.1~55.4 |

라이브러리에 적응형 화질 조절이 켜져 있어서 프레임이 떨어질 것 같으면 내부 해상도를 알아서 낮춘다. 측정할 때 실제로 그린 해상도는 게이트 앞 1240×697, 거리 중간 942×530이었고 조명은 거기서 다시 20% 해상도로 계산했다. 화면이 전체적으로 살짝 뿌옇게 보이는 건 이것 때문이다.

## 배포

정적 파일뿐이라 fly.io에 nginx 컨테이너 하나로 올렸다. 도쿄 리전 shared-cpu-1x 256MB 머신 1대고, 아무도 안 들어오면 꺼진다. three.js와 라이브러리는 jsDelivr에서 버전을 고정해 불러온다. 첫 배포 때 IP 자동 할당이 실패해서 IPv4, IPv6를 따로 붙여 줬다. 배포 후 브라우저로 열어 보니 콘솔 오류 없이 52fps로 잘 돌았다.

## 아직 남은 것

1. 실제 휴대폰에서는 성능을 재 보지 않았다. 모바일은 M4 Pro에서 터치를 흉내 내서 확인한 게 전부다.
2. Safari, Firefox에서는 안 열어 봤다.
3. 별도 코드 리뷰를 받지 않았다.
4. WebGL2가 안 되는 환경에서는 레이트레이싱 없이 일반 렌더링으로 바뀐다.
